# 로그·이벤트 기반 장애 원인 분석 에이전트

> 현재 상태: 프로젝트 주제 선정 및 MVP 설계 단계

서버 로그, 에러 트레이스, 메트릭, 배포 이력과 Git 변경사항을 시간순으로 연결하여 서비스 장애의 원인 후보를 찾고, 판단 근거와 대응 방안을 함께 제시하는 Agentic AI를 만드는 것이 목표입니다.





## 후보 1. 최근 배포와 장애의 인과관계 분석 에이전트


서비스 장애가 최근 배포 때문에 발생했는지 판단하고, 어떤 커밋의 어떤 변경이 장애를 유발했는지 관련 로그·트레이스·지표와 함께 제시하는 에이전트

### 해결하려는 문제

장애 발생 직후 운영자는 빠른 롤백과 원인 파악이 필요합니다. 이를 위해 변경된 코드와 설정, 로그 및 트레이스를 각각 확인해야하고 정보가 여러 도구에 흩어져 있어 원인 후보를 찾는 데 시간이 걸립니다.


---

## 후보 2. 관측 데이터 기반 통합 장애 진단 에이전트

서버, Kubernetes, 애플리케이션, 데이터 계층의 관측 데이터를 통합하여 장애 영향 범위를 파악하고, 원인 가설을 도구로 검증한 뒤 완화책·근본 해결책·재발 방지책을 근거와 함께 제시하는 에이전트

### 해결하려는 문제

사용자 오류가 애플리케이션 문제인지, Pod 재시작이나 리소스 부족인지, DB connection pool 고갈인지, Redis 또는 메시지 큐 지연인지 판단하려면 로그 기반으로 여러 계층을 오가며 데이터를 확인해야 합니다. 이 후보는 서비스 의존 관계(+코드?) 기준으로 장애의 시작 지점과 전파 범위를 좁혀 원인을 특정합니다.
